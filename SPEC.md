# ТЗ MVP: телеграм-бот-тренажёр по матанализу

Nov 19, 2026 · @Timofey

Бот-тренажёр для группы \~25 студентов: решают параметризованные задачи по контрольным точкам, бот проверяет каждый шаг через sympy, преподаватель получает статистику без ручной проверки. Запуск — Nov 25, 2026.

## 1. Рамки MVP

Бот — тренажёр, а не инструмент оценивания: баллы за правильность не ставим, только бонус за регулярность (дни с активностью).

**Входит в MVP:**

- Режим «Тренировка»: задача из шаблона со случайными параметрами, решение по контрольным точкам, автопроверка каждой точки.
- Режим «Блиц»: «выбери метод» за 10 секунд, 10 задач за серию.
- Одна статическая подсказка на контрольную точку (текст из шаблона), факт взятия логируется.
- Два хода решения на выбор под условием: «По шагам» (все контрольные точки) или «Сразу ответ» (только первообразная; после ❌ можно перейти на шаги).
- Выход из задачи в любой момент: кнопка \[✖ Выйти из задачи\] и команда /stop; брошенная задача не портит статистику.
- Два способа ввести ответ на выбор студента: набрать текстом или прислать фото итоговой формулы (распознаёт vision-модель). В обоих случаях — превью картинкой и подтверждение перед проверкой. Промежуточные шаги — кнопками.
- Темы: только неопределённые интегралы (Демидович, отдел III, № 1628–2180). Пределы — следующим релизом.
- Команда /export для преподавателя: XLSX со статистикой.

**Не входит (v2):** лестница подсказок, LLM-диалог «застрял», Elo-адаптивность, карточки по билетам, тепловая карта, фото полных решений, Mini App с математической клавиатурой.

**Критерии готовности к 25.11:**

- ≥ 15 шаблонов по интегралам, каждый прогнан автотестом на 50 сгенерированных экземплярах.
- Для каждого шаблона эталонный ответ принимается, а типовые ошибки (знак, потерянный множитель) отклоняются.
- Ответ бота на проверку < 3 с, зависший sympy убивается по таймауту.

## 2. Модель задачи

Шаблон = текст с параметрами + ограничения на параметры + список контрольных точек. Храним в YAML, по файлу на тему, в git. Эталонные выражения — строки sympy, параметры подставляются при генерации.

```yaml
id: int_trig_universal_01
topic: indef_integral.trig
source: "Демидович, № 2028 (аналог)"
difficulty: B            # A | B | C
var: x
params:
  a: {int: [2, 7]}
  b: {int: [1, 6]}
constraints: ["a > b"]
statement: "\\int \\frac{dx}{{a} + {b}\\cos x}"
integrand: "1/(a + b*cos(x))"
checkpoints:
  - type: choice
    prompt: "Какую замену применишь?"
    options: ["t = cos x", "t = sin x", "t = tg x", "t = tg(x/2)"]
    correct: ["t = tg(x/2)"]
    hint: "Функция не нечётна ни по sin, ни по cos и не чётна по паре."
  - type: transformed_integrand      # интеграл после замены, по переменной t
    prompt: "Запиши подынтегральную функцию после замены (по t)"
    var: t
    expected: "2/((a+b) + (a-b)*t**2)"
    skippable: true                  # свой путь → судим по ответу
    hint: "cos x = (1-t²)/(1+t²), dx = 2dt/(1+t²)"
  - type: antiderivative
    prompt: "Ответ (с +C)"
    reference: "2/sqrt(a**2-b**2)*atan(sqrt((a-b)/(a+b))*tan(x/2))"
    domain: [-3.0, 3.0]              # откуда брать точки для численной проверки
blitz_method: "универсальная замена"   # этот же шаблон идёт в блиц
```

**Типы контрольных точек:**

| Тип | Что вводит студент | Как проверяем |
| --- | --- | --- |
| choice | кнопка | вхождение в `correct` (допускается несколько верных) |
| expr | выражение | эквивалентность с `expected` |
| transformed\_integrand | выражение по t | эквивалентность с эталоном; если не сошлось и skippable — идём дальше без штрафа |
| antiderivative | первообразная | F′ − f = 0 численно в точках domain (см. раздел 3) |
| series | разложение до o(xⁿ) | совпадение коэффициентов до степени n через `series()` |
| value | число / выражение без x (предел) | точное равенство с эталоном; ±∞ вводится как `oo` |

**Промежуточные точки — кнопками, финальный ответ — вводом.** По умолчанию `transformed_integrand` и `expr` показываются как выбор из 4 вариантов (картинки формул). Дистракторы генерируются из эталона автоматически: знак (×(−1)), множитель (×2, ×½), потерянный множитель от dx (например, 2/(1+t²) при универсальной замене), по желанию — ручные дистракторы из поля `distractors` шаблона. Дистракторы, эквивалентные эталону или друг другу, отбрасываются через тот же checker. На уровне C промежуточные точки можно переключить на ввод (`input_mode: free`).

Пример цепочки для предела lim (e^(ax) − 1 − ax)/x²: choice («Тейлор / Лопиталь / эквивалентности», верны первые два) → series (разложи числитель до o(x²)) → value (a²/2).

**Генерация экземпляра:** сэмплируем параметры → проверяем constraints → самопроверка шаблона (diff(reference) == integrand численно, для пределов limit() == value) → сохраняем экземпляр в БД. Самопроверка ловит опечатки в шаблонах до того, как их увидит студент.

## 3. Проверка ответов

Проверка детерминированная, без LLM: сначала символьно, при неудаче численно.

**Парсинг ввода**

1. Нормализация строки: `^` → `**`, `tg` → `tan`, `ctg` → `cot`, `arctg` → `atan`, `ln` → `log`, `√`/`sqrt`, запятая → точка, убрать `+C` в конце.
2. `parse_expr` с трансформациями `implicit_multiplication_application` (чтобы `2x`, `2sin x`, `x(x+1)` парсились).
3. Белый список имён через `local_dict` + пустой `global_dict` без builtins; длина ввода ≤ 300 символов; запрещены `_`, `.`, `lambda`, `import`. `parse_expr` внутри делает eval — без этих ограничений это дыра.
4. Превью: `sympy.latex(expr)` → matplotlib mathtext → PNG → «Ты имел в виду это?» с кнопками \[Да, проверь\] \[Исправить\].

**Ввод фото итоговой формулы**

1. Студент жмёт \[Отправить фото\] и фотографирует только ответ (одну формулу), не всё решение.
2. Бот уменьшает картинку (до \~1 Мп) и отправляет в vision-модель (дешёвая модель Claude или GPT; альтернатива — Mathpix, если точности не хватит).
3. Промпт: транскрибировать формулу дословно в синтаксис sympy, ничего не исправлять и не упрощать; если формул несколько или нечитаемо — вернуть `UNREADABLE`. Условие задачи и эталон модели **не передаём** — иначе она будет «чинить» ошибки студента.
4. Результат идёт через тот же парсер → превью «Ты написал это?» → \[Да, проверь\] \[Исправить\]. «Исправить» присылает распознанную строку текстом: студент правит пару символов, а не набирает заново.
5. `UNREADABLE` или ошибка API → «Не разобрал, пересними крупнее или введи текстом».

Правила: в БД храним только Telegram `file_id` и распознанную строку (сами фото не скачиваем на диск); лимит 30 фото в день на студента; таймаут запроса к модели 15 с. В `attempts` пишем `input_method` (text | photo) и факт правки после OCR — по ним оценим точность распознавания. Стоимость на 25 человек — единицы долларов в месяц.

**Эквивалентность выражений (expr, transformed\_integrand)**

1. `simplify(user - expected) == 0` → верно.
2. Иначе численно: 12 случайных точек из domain, относительная погрешность 1e-8; точки, где одно из выражений не определено или комплексное, выбрасываем; нужно ≥ 8 валидных точек.

**Первообразная (antiderivative)**

- Проверяем F′ = f, а не F = F\_ref: так автоматически принимается любая форма и любая константа.
- Численно по точкам domain; ln|u| и ln u оба принимаем (производные совпадают там, где оба вещественны). Потеря модуля в MVP не штрафуем, только пишем замечание.

**Типовые ошибки — осмысленная обратная связь.** Если неверно, проверяем: user = −expected («проверь знак»), user/expected = const («потерян множитель»), для первообразной — F′/f = const. Дёшево и даёт подсказку без LLM.

**Изоляция:** проверка в отдельном процессе, который убивается по таймауту 3 с (`pebble.ProcessPool`; у стандартного `ProcessPoolExecutor` таймаут не убивает зависший воркер). Таймаут simplify → сразу численная ветка; таймаут всего → «не смог проверить, упрости запись» и статус `error` в БД (эти случаи ты просматриваешь раз в неделю).

**Автотесты (pytest):** на каждый шаблон — эталон принимается, эквивалентная форма (через `expand`/`trigsimp`) принимается, эталон·(−1) и эталон·2 отклоняются, генерация 50 экземпляров проходит самопроверку.

## 4. Сценарии бота

**Регистрация (/start)**

1. Студент вводит код группы (ты скажешь его на паре) — чужие не зайдут.
2. Вводит имя и фамилию (списка группы нет). Дубли и опечатки правишь командой /rename, лишних удаляешь /kick.
3. Короткая инструкция по синтаксису (картинка-шпаргалка: `sqrt(x)`, `x^(1/3)`, `tg x`, `arctg`, `ln`, `e^x`, `pi`, `oo`; в первообразной обязательно `+ C`).

**Тренировка (/train)**

1. Выбор темы → уровня A/B/C (в MVP выбирает сам студент). Отдельная кнопка «🎲 Вразнобой» — задачи из всех тем (уровень A/B/C или «Любой»), настоящая тема не показывается, один шаблон подряд не повторяется. В ходе «По шагам» первый шаг — «Каким методом будешь решать?» со всеми методами банка в фиксированном порядке (шаги шаблона выдают метод); методы из `method_alternatives` шаблона засчитываются с пометкой «Сработает, но можно короче». В логе этот шаг — `checkpoint_type = method`, `checkpoint_idx = -1`.
2. Бот шлёт условие картинкой (рендер LaTeX) и кнопки \[По шагам\] \[Сразу ответ\]. «Сразу ответ» — сразу ввод первообразной, подсказка — из первой точки (про метод), после ❌ есть \[Решать по шагам\] (возврат к первой точке, потраченные на ответ попытки сохраняются).
3. По очереди контрольные точки. На промежуточных — кнопки; на финальном ответе — \[Ввести текстом\] или \[Отправить фото\] → превью → проверка → ✅ или ❌ с диагнозом («проверь знак»).
4. После ❌: \[Попробовать ещё\] \[Подсказка\] \[Показать ответ и идти дальше\]. Попыток не больше 3 на точку.
5. Итог задачи: сколько точек с первой попытки + \[Следующая задача\] \[Другая тема\].
6. На любом шаге — \[✖ Выйти из задачи\] или /stop, без подтверждения: сессия получает статус `dropped`, бот предлагает \[Другая задача этой темы\] \[Меню тем\]. Начало новой задачи поверх незаконченной — тоже `dropped`.

**Блиц (/blitz)** — 10 задач подряд, у каждой 4 кнопки с методами, таймер 10 с (ответ после таймера = пропуск). В конце счёт и разбор ошибок: по каждой — правильный метод и признак, по которому его узнать (поле `hint` первой точки). Задачи берутся из тех же шаблонов (поле `blitz_method`) — отдельный банк не нужен.

**Личная статистика (/me)** — решено задач по темам, % точек с первой попытки, лучший блиц, серия дней подряд.

**Преподаватель (только твой tg\_id):** /export — XLSX; /students — кто зарегистрирован; /broadcast — сообщение всем («к среде пройдите блиц по Лопиталю»); /reload — перечитать YAML-шаблоны без рестарта.

**Напоминание:** если студент не заходил 3 дня — одно сообщение с кнопкой \[Блиц на 2 минуты\], не чаще раза в неделю.

## 5. Банк задач

Банк строим по Демидовичу (изд. 1995), отдел III, № 1628–2180. Один шаблон = серия однотипных номеров, в `source` — номера-прототипы. Номера, где параметр уже в условии (1739, 1740, 1743, 1778–1790, 1836, 1846, 2016, 2017, 2019–2024, 2028, 2030, 2031, 2033, 2063, 2074, 2075, 2124, 2125), ложатся в генератор напрямую; в остальных параметризуем числовые коэффициенты.

**Карта отдела III:**

| §3 Иррациональные | 1926–1990 | корни из дробно-линейных, квадратичные иррациональности, Эйлер (1966–1970), Чебышёв (1981–1989) |

## 6. Данные и выгрузка

Одна SQLite-база. Храним только tg\_id и ФИО из списка группы; сырой ввод логируем целиком — по нему видно типовые ошибки и дыры в парсере.

```sql
CREATE TABLE students  (id INTEGER PRIMARY KEY, full_name TEXT UNIQUE, tg_id INTEGER UNIQUE, registered_at TEXT);
CREATE TABLE instances (id INTEGER PRIMARY KEY, template_id TEXT, topic TEXT, difficulty TEXT,
                        params_json TEXT, created_at TEXT);
CREATE TABLE sessions  (id INTEGER PRIMARY KEY, student_id INT, instance_id INT, mode TEXT,  -- train | train_direct | blitz
                        started_at TEXT, finished_at TEXT, status TEXT);              -- solved | revealed | dropped | abandoned
CREATE TABLE attempts  (id INTEGER PRIMARY KEY, session_id INT, checkpoint_idx INT, checkpoint_type TEXT,
                        raw_input TEXT, verdict TEXT,          -- ok | wrong | sign | factor | no_const | parse_error | timeout
                                                               -- | revealed («Показать ответ») | skip (блиц: время вышло)
                        input_method TEXT, ocr_raw TEXT, ocr_edited INT,  -- text | photo | button
                        hint_used INT, attempt_no INT, latency_ms INT, created_at TEXT);
CREATE TABLE blitz_runs (id INTEGER PRIMARY KEY, student_id INT, started_at TEXT, finished_at TEXT,
                         score INT, total INT);                 -- недоигранная серия: finished_at IS NULL
CREATE TABLE ocr_requests (id INTEGER PRIMARY KEY, student_id INT, file_id TEXT,  -- сами фото не храним
                           recognized TEXT, status TEXT,        -- ok | unreadable | error
                           created_at TEXT, markdown TEXT,      -- markdown — сырой ответ Yandex OCR
                           attempt_id INT);                     -- попытка, если распознанное отправили на проверку
```

Все отметки времени — ISO с часовым поясом Europe/Minsk: дни в /me и /export не зависят от пояса сервера. Задачи блица пишутся и в sessions/attempts (mode = blitz, raw\_input = выбранный метод, checkpoint\_type = blitz) — из них матрица путаницы методов.

**Отчёт /export (XLSX, 3 листа):**

| Лист | Строки × столбцы | Зачем |
| --- | --- | --- |
| Студенты | студент × (дней активности, задач, % точек с 1-й попытки по каждой теме, лучший блиц) | бонус за регулярность, кто отстаёт |
| Шаблоны | шаблон × контрольная точка → % ошибок, топ-3 неверных ввода | что разбирать в среду: на каком шаге ломаются |
| Блиц | правильный метод × выбранный метод (матрица ошибок) | какие типы путают между собой |

Тепловая карта и автосводка ко вторнику — v2; в MVP те же данные смотришь в XLSX или в pandas.

```
  data/       templates/*.yaml, students.csv, bot.db
  tests/      test_parser.py, test_checker.py, test_templates.py
```

**Деплой:** на пилот — старый домашний ноут на Windows, постоянно включённый. Настройки: сон отключён при питании от сети и при закрытии крышки; бот как служба через NSSM (или Планировщик заданий «при запуске») с автоперезапуском; часы активности Windows Update, чтобы не было ночных перезагрузок; бэкап `bot.db` раз в сутки (папка в облаке). Long polling не требует белого IP и проброса портов. Если пилот зайдёт — переезд на VPS за \~5 $/мес без изменений кода.
